# CareCircle: friction log

Problems hit while building CareCircle (a self-hosted MCP server for the Alexa+ track) with the MCP Python SDK 2.3.0
and spec 2025-11-25, each with what I expected, what actually happened, how I worked around it, and a suggestion.

| # | Task attempted | Steps taken | Expected | Actual | Severity | Workaround | Suggestion |
|---|---|---|---|---|---|---|---|
| 1 | Start an MCP server from the getting-started guide | `pip install mcp`, then `from mcp.server.fastmcp import FastMCP` | Server starts | `ModuleNotFoundError`: FastMCP was removed in mcp 2.x | Medium | Switched to `from mcp.server.mcpserver import MCPServer` after reading the migration guide | Update the getting-started docs and snippets for v2, or keep a deprecated alias for one release |
| 2 | Add an MCP App (UI-bound tool) | Created `MCPServer(extensions=[apps])`, then decorated `@apps.tool(resource_uri="ui://…")` below it | Tool appears in `tools/list` | Tool silently missing (9 of 10 tools listed), no warning | High (silent failure) | Moved all `Apps()` registrations above the `MCPServer(...)` call, since extensions are applied at construction | Warn when an extension gains tools after it has been applied, or register lazily |
| 3 | Return structured tool output | Annotated tools `-> dict` | `structuredContent` populated | Only text content returned | Low | Annotated `-> dict[str, Any]` | Document which return annotations produce structured output |
| 4 | Deploy publicly with DNS-rebinding protection kept on | Bound to `0.0.0.0` for Render; read the SDK source to see when protection applies; tested with a public `Host` header | Protection on, public hostname accepted | Protection is auto-enabled only for localhost binds, so a `0.0.0.0` deploy is silently unprotected. Once enabled, any host not listed gets a bare `421` with no explanation | High | `TransportSecuritySettings(allowed_hosts=[localhost…, public host])` read from an env var; verified 200 for the public host and 421 for a spoofed one | Warn when serving `0.0.0.0` unprotected; include the rejected host in the 421 body; support an `MCP_ALLOWED_HOSTS` env var |
| 5 | Make Alexa+ speak first (medication reminder) | Looked for a way for an MCP server to push a prompt to a voice assistant | A proactive notification capability | None in the spec; notifications only reach an already-connected client | Medium | The device polls a `check_nudges` tool every few seconds | A proactive / "attention request" capability for voice hosts |
| 6 | Test on a real Alexa+ device | Looked for a developer path to attach a self-hosted MCP server to an Echo | Test on my own Echo | Not publicly available | Medium | Built an Echo Show–style simulator that is a real MCP client | An Alexa+ developer sandbox for self-hosted MCP servers |
| 7 | Deploy from a Render blueprint | Opened the one-click deploy link and clicked Apply | Service created | Nothing deployed: the required "Blueprint Name" field was empty, and the error was easy to miss | Low | Filled in the name and clicked Deploy Blueprint | Pre-fill the blueprint name from the repo name |
